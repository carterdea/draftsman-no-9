# Artifact Storage Plan

Scope: durable artifact storage for screenshots, video, traces, and log bundles generated by Draftsman runs.

## Decisions

- Production artifact backend: Cloudflare R2 (S3-compatible API).
- Development artifact backend: local filesystem via bind-mounted host directory.
- Do not rely on container-local filesystem paths for persistence (`docker run --rm` removes container storage on exit).
- Persist artifact metadata and pointers in Postgres (`job_artifacts`), not blob contents.
- Retention baseline:
- heavy artifacts (`screenshot`, `video`, `playwright_trace`, log bundles): 90 days
- durable links (`pr_url`, delivery comment links): long-term

## Storage Model

### Object Key Convention

- Bucket: `draftsman-artifacts` (env-specific suffix recommended)
- Key format: `{env}/{yyyy}/{mm}/{job_id}/{artifact_kind}/{artifact_id}.{ext}`

Example:

- `prod/2026/02/8f9c.../screenshot/after-fix.png`

### DB Pointer Contract (`job_artifacts`)

- `job_id`
- `kind`
- `storage_provider` (`r2` or `local_fs`)
- `uri` (object key or file path)
- `metadata_json`:
- content type
- byte size
- sha256
- capture phase (for example `repro` or `post_fix`)
- optional delivery target ids (trello attachment id, slack file id)

## Access Pattern

- Worker uploads artifact immediately after creation.
- Worker writes `job_artifacts` row with immutable metadata pointer.
- Delivery adapters consume pointer and attach/link to Trello/Slack as needed.
- Audit API returns artifact pointers; UI resolves via signed URL when needed.

## Environments

### Production

- Use R2 S3-compatible credentials from environment variables.
- Upload with server-side encryption and strict bucket policy.
- Use signed URLs for private reads in internal dashboard.
- Apply R2 lifecycle expiration for heavy artifacts at 90 days.

### Local Development

- Write artifacts to mounted directory (for example `./.draftsman-artifacts`).
- Never write artifacts to container-only paths.
- Register as `storage_provider=local_fs`.

## Failure Behavior

- Artifact upload failure is non-fatal to run completion unless policy marks artifact as required.
- Record `delivery.attachment_failed` and `artifact.upload_failed` audit events with reason.
- Continue with other artifacts and delivery steps.
